- Hodii is a Kenyan property marketplace. Brand name, domain, legal entity and mailboxes live only in src/lib/brand.ts (site.ts re-exports from it); never hardcode them elsewhere. No news, stories, readers, comments or newsletter code remains; do not reintroduce it.
- The one site header is src/components/site-header.tsx (category links open /properties searches via categorySearch). The "List a property" button goes to sign-up. Footer links open /info/<slugify(label)>; every label in footerSections (src/data/site-content.ts) needs a page in src/data/info-pages.ts or legal-pages.ts, which test/pages.test.ts enforces. Legal pages are Kenya-specific drafts and need advocate review before launch.
- The database name comes from MONGODB_DB (default "hodii").
- Every content route sets a self-referencing relative canonical link. Property pages should emit structured data that matches what the page shows.
- MongoDB validators and indexes live in src/lib/mongodb; mongodb/schema.json is generated from them (scripts/generate-mongodb-schema.ts) and applied with scripts/apply-mongodb-schema.ts, so database and application shapes cannot drift. mongodb/schema.json is JSON-Schema dialect; translate const/exclusiveMinimum/format before collMod.
- Session and rate-limit TTL fields use BSON Dates; check expiry on each protected request because TTL cleanup is asynchronous.
- mongodb's tr46 is patched (patches/) to require "punycode" instead of "punycode/"; the serverless build cannot resolve the trailing-slash form.
- Sign-up runs only through a server function that creates an already-confirmed account; per-address counts live in `signupAttempts` and sign-up is refused past the limit, so the app never sends auth emails (no confirmation, no password reset). Usernames are unique ignoring case (a collated index on users.username).
- Sign-in is email and password only; social providers are disabled because account data must live in the app's own MongoDB.
- Request protection (probe/scanner blocking, per-visitor rate limits with escalating temporary bans, body/URL caps, security headers, cache headers) lives in src/lib/protection.ts and runs in src/server.ts before the app; it is per-isolate and complements the hosting edge flood protection.
- The site builds with @lovable.dev/vite-tanstack-config (Cloudflare Worker target) and reads MONGODB_URI / COMMUNITY_ENCRYPTION_KEY / ADMIN_USERNAME / ADMIN_PASSWORD from project secrets.
- Direct children of the root .app-shell column are forced to full width (styles.css) because mx-auto blocks in a flex column shrink to their content and overflow phone screens.
- The property data model lives in src/lib/mongodb (property-schemas, taxonomy, limits, kenya, property-rules, indexes) and permissions in src/lib/access.ts; docs/data-model.md explains both. Never hardcode listing limits, property types or features elsewhere.
- A person has one sign-in; agency membership (owner, admin, agent) decides which dashboards they get. getMe returns accountType, agencies and the default dashboard path. Account functions (username check, summary, rename, delete) are in src/lib/account.functions.ts; deleting an account refuses when the person is the only owner of an agency and unlinks their enquiries (deleteUserData).
- Public listing reads and writes live in src/lib/properties.server.ts with server functions in properties.functions.ts; the agency dashboard's server logic is dashboard.server.ts (every entry point starts with requireMember), and staff moderation is moderation.server.ts behind the admin Moderation tab. Search state lives in the URL (src/lib/search-url.ts); /section/<slug> redirects to the matching /properties search via CATEGORY_SEARCHES.
- The admin dashboard (src/routes/admin.tsx) has Overview, Analytics (market funnel, series, top listings and agencies, plus site traffic), Moderation, Listings, Agencies, Users (admin only), Site & security, Activity, Team and My account. Its queries are in admin-analytics.server.ts; every function in admin.functions.ts checks the admin role first.
- Phone numbers are never in page data: revealListingContact fetches them on click, which is also what counts a phone reveal. Photos upload directly to Cloudinary using signatures from images.server.ts; only URLs inside the agency's own folder are accepted when a listing is saved.
- After adding or renaming a route file the route tree must be regenerated (the dev server and build do it). If you regenerate it outside Vite, keep the `Register` block at the end of src/routeTree.gen.ts.
- Comments on listings (what the news site called comments) live in comments.server.ts / comments.functions.ts with the UI in components/property/comments.tsx: text encrypted at rest, threaded replies up to LIMITS.replyDepthMax, likes, edit within LIMITS.commentEditWindowMinutes, soft delete, per-listing and burst limits, the comments_enabled site switch, a Comments tab in the admin (editors can remove), and a "Your comments" list on /profile. Collections: propertyComments, propertyCommentLikes. Account deletion blanks the person's comments.
- "List a property" buttons all link to /list-property, which routes by state: signed out → sign-up as an agency, then back; agency member who can add listings → new-listing form; otherwise → create an agency.
- Photos: a save may keep photos already on the listing from any host (imports, bootstrapped listings), but any photo added in that save must be a direct upload into the agency's own Cloudinary folder (foreignNewPhotos in images.server.ts, enforced in saveListing). Importers write images straight to the database and are not subject to this.
- Notifications are in-site only (the bell and /notifications; collection `notifications`, 90-day expiry); nothing is emailed. notifications.server.ts has `notify`, which never throws, and the sweep that creates saved-search matches and price drops when a person's bell is checked, so listings written by an importer straight into MongoDB are covered. Events that notify: enquiries, listing and agency decisions, suspensions, team invitations and replies, comment replies, likes on a comment, comments on a listing, and listings expiring in 7 days or expired (sweepListingExpiry).
- Team invitations: an existing account gets the invitation in its bell and accepts or declines; an email with no account yet keeps the pending invitation (the address is stored encrypted so the Team page can show it), and it reaches the person at sign-up (`attachInvitations`). Pending invitations count toward the team limit and can be cancelled.
- Saved page (/saved): saved properties and saved searches (frequency instant, daily, weekly or off). The "Save search" button is on /properties.
- Live updates: components/live-updates.tsx polls getLiveStamp every 15 seconds (edge-cached 5 s), and reloads loader-backed lists and nearby lists when it changes. The bell polls every 30 s, comments every 20 s, agency enquiries and listings and the admin overview every 30 s. There are no change streams or websockets, because the host is serverless.
- Importers write to MongoDB directly: see docs/importing.md.
- Listing pages end with "You might also like" (similar.server.ts: same kind, area and price first, widening to county, region and category, nearest price first, up to 8) and "More from this agency" (4).
- Staff have no bell: the admin sidebar shows a live badge on Moderation (listings + agencies + reports waiting, refreshed every 30 s via adminPendingCounts) and puts the number in the browser tab title.

## Part 7 additions
- Agency profile: `story`, `tagline`, `services`, `hours`, `foundedYear`, `socials`, `cover` on the agency (edited in dashboard Settings, including cover and logo uploads). Public page `routes/agency.$slug.tsx` shows them with the team, reviews and the same search filters as `/properties` limited to the agency (`loadAgencyPage(db, slug, params)`).
- Reviews: `agencyReviews` collection, `lib/agency-reviews.server.ts`, rules in `lib/review-rules.ts`. One per person per agency, editable, 5 new reviews a day, agency staff cannot review their own agency, owners/admins reply once, 3 reports hide a review, staff moderate in Admin > Reviews. `agencies.rating {count, avg}` is recomputed on every change. `AgencyBadge.rating` is available to cards.
- Directory: `/agencies` (`loadAgencyDirectory`), linked from the header.
- Avatars: `users.avatar`, `getAvatarSignature`/`setMyAvatar` (own `hodii/avatars/<userId>/` folder only), `AvatarEditor` on `/profile`, `SessionUser.avatarUrl`.

- Enquiry conversations: `enquiry-threads.server.ts` (collection `enquiryMessages`). Agency staff who can manage a lead reply from the enquiries page; the enquirer sees the thread under "Your enquiries" and can answer once the agency has written. Replies notify the other side (in-site), set `firstResponseAt` and move `new` to `contacted`, and are limited to 20 per hour per person. Guest enquiries (no userId) cannot be replied to in-site.
- Bulk work: CSV import (`bulk-import.ts`, drafts only, photos added by hand, max 200 rows), bulk actions (`bulk.server.ts`, max 100, deletes need a typed phrase plus password), exports (`exportListingsCsv`, `adminExport`; formula-defused, no emails).

- Part 9 features: compare (`lib/compare.ts` keeps up to 4 ids in localStorage; `/compare?ids=` is shareable; `compareCards`), calculators (`lib/calculators.ts`, `/tools`), location pages (`/locations`, `/locations/$county`, `/locations/$county/$area`, `loadLocation`; area pages return 404 when nothing is listed), sitemap index (`lib/sitemap.ts`, `/sitemap.xml` and `/sitemaps/$name`), PWA (`public/sw.js`, manifest, offline page), "Download my data" (`my-data.server.ts`, `exportMyData`, password required), error alerts (`error-alerts.ts/.server.ts`, collection `errorEvents`, admin Errors tab, optional ALERT_WEBHOOK_URL, `error-report.functions.ts` for browser errors), staff two-step sign-in (`totp.ts`, `admin-2fa.server.ts`; adminLogin takes an optional `code`; ADMIN_REQUIRE_2FA=1 forces it). See docs/operations.md.
- Legal pages live in `src/data/legal-pages.ts` (terms, privacy, cookies, accessibility, help). They must be reviewed by a Kenyan advocate and updated when features change; bump LEGAL_UPDATED in brand.ts (and TERMS_VERSION in recovery.ts if acceptance should be asked again).
- Search: typed words must match anywhere in a listing (listing-search.ts `tokenMatch`); sentences are read by query-intent.ts into filters; default "Best match" ordering is rank.ts (match + freshness + capped Boost/Premium lift) then `mixPaid`. AI search (ai-search.server.ts, Groq keys in GROQ_API_KEYS, rotated by key-pool.ts) only returns filters validated by ai-criteria.ts; allowances are counted in `aiUsage` and set in admin Settings. See docs/search.md. Every filter dropdown uses components/ui/pick.tsx (nested button list), not a native select; shared option lists live in lib/pick-options.ts.
- Search runs as people type or click (debounced); if nothing matches exactly, close spellings are tried (fuzzyPattern). Results load by infinite scroll (InfiniteResults); "newest" is never the default order. Dark theme is the default everywhere (set on the html element in routes/__root.tsx; colours come from the dark tokens in styles.css); Nairobi is first in county lists; page width is max-w-[112rem].
- Basic listing cap: lib/basic-limit.ts (pure rules), basic-space.server.ts (usage, gate, freeze), spacePacks for extra space; frozen status; paid listings never counted. See docs/payments.md.
